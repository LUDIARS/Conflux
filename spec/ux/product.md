## 目標体験

遊ぶ → 感想や改善案を話す → AI が困り事・面白かった点・変更案を整理する → チームが次に試す案を選ぶ
→ Cc 経由で実装する → 成果物を遊んで確かめる → 結果を次の議論へ戻す。

実装量や技術的な苦労ではなく、遊びの面白さを育てる機会を増やす。短い感想・非同期の意見も拾う。
採否は人間が判断し、見送った理由・過去の試行も残す。

## 画面の入口

プロジェクトを開くと、そのプロジェクトの潮流・亜流・本流と分岐・合流をグラフで表示する
(`GET /projects/:code`)。グラフのノードを選ぶと、同じ選択対象について
コンセプト・改修履歴・ルール差分・コメント/評価・成果物・作業依頼・合流判断を同じ画面に並べる。
グラフの選択対象と詳細の対象は常に同じ亜流 id から引く (CF-GRAPH-001)。

## Web UI と Tela オーバーレイ UI (Pf CF-WEB-001 / CF-DESIGN-001 追記)

人間の指示 (2026-09-18): 「Conflux は WebUI と Tela のオーバーレイ UI の両方を持つ。まずは WebUI 対応。スマホにも対応。」

- 体験: PC でもスマホでも、対象プロジェクトと流れを見失わずにコンセプト・ルール差分・コメント・
  試遊成果物を確認し、次の改善 (作業依頼・合流判断) へ進める。
- 業務状態の所有者は既存 7 ドメイン。Web と Tela は共通の use case / 読み取りモデルを使う
  **表示・入力 adapter** で、UI ごとに業務ルール・履歴・権限判定を複製しない。
- Web: プロジェクト選択 → 流れグラフ → 選択した潮流/亜流の詳細。PC はグラフと詳細を並べ、
  スマホは同じ選択 id を保ってグラフ/詳細を切り替える。詳細はコンセプト・ルール差分・対話・成果物・
  作業依頼・合流判断へ迷わず移れる。グラフの移動・拡大縮小は操作ボタンを備え、touch や hover だけを
  必須にしない。グラフを補う流れ一覧も同じ選択へ遷移する。技術設定は初期画面の主役にしない。
- Tela: ホスト接続とオーバーレイ表示は **後続 (今回範囲外・未実装)**。
- 受入基準案 (幅 320/390/768/1280px、44px タップ領域、16px 入力、label/focus/keyboard、長文・多数ノード・
  空状態・通信失敗) と実装の対応は `spec/feature/web-ui.md`。**ブラウザ・実機での UX 達成確認は未実施。**

## 人間が確定した要件 (Pf CF-DESIGN-001「人間が指定した機能」)

1. `evolution/xxxx/yyyy` の xxxx は潮流、yyyy は亜流。全体を流れと呼ぶ。亜流ごとに本流 main を持つ。作業は feature/xxxx 等。
2. 潮流・亜流をグラフビューにし、コンセプト・改修・ルール変更を可視化する。
3. 潮流を正式ルールと決める UI を設け、合流と呼ぶ。
4. Cc に Conflux Flow を独立設定として追加 (Rv/GitHub と並行)。対象は KD と Mp。現行 KD=Rv、Mp=GitHub。**Cf 有効化は未反映**。
5. Cf コメント欄。Cf Flow のゲームのデバッグ画面からコメント投稿・潮流評価。
6. Cf から Cc へ spawn。プロジェクト主軸で子会社/Discord/Slack 等の宛先を事前設定。
7. 各潮流の結果に必ず成果物。ビルド DL またはデプロイ。ビルドはフロー連動で自動化し Cc フックで管理。デプロイは管理職以上のみ。
8. Cc フックは作業開始前に実ブランチと対象潮流を確認し、混入を警告して対象ブランチへ切り替える (Cc 側 PR #1893、未配備)。
9. 通常フローでも起点は main。PR 提出後の別作業は classifier と hook の二重チェック (Cc 所有)。

## 確定した事項 (2026-09-20 neco 判断)

いずれもプロジェクト設定のデータのままで、個別に上書きできる。未指定のときにこの値が入る。

| 事項 | 確定内容 | 理由 |
|---|---|---|
| 本流の物理命名 | `evolution/<潮流>/<亜流>/main` (`suffix-main`)。作業接頭辞は `feature` | git は `evolution/x/y` とその配下を同時に持てない。亜流自身を本流にすると配下の名前空間を恒久的に塞ぐ |
| 評価の尺度/項目 | 「面白さ」1〜5 の一軸 + 自由文コメント | CF-UX-1 は短い・非同期の意見を拾うこと。軸を増やすたびに投稿しない理由が増える。軸の追加は一軸で足りないと分かってからで間に合う |
| 自動ビルドの契機・平台 | 契機 = 亜流の本流へ改修が記録された時 (`variant-mainline-updated`)、平台 = web | DL 無しで違いを遊び比べられるのが CF-UX-2 への最短路 |
| 成果物の保管・保持 | Cf は成果物本体を保管せず、Cc フックが報告した URI を参照するだけ (従来設計の追認) | 保管の責務を二重に持たない |
| デプロイ先 | 環境は「試遊」1 つから | まず試遊できることが目的。増やすのは必要が出てから |
| 合流時の承認手順 | 判断者と理由の記録のみ必須。1 名で成立し、デプロイの管理職要件は転用しない (従来設計の追認) | 合流は「正式ルールにする」判断であって配布権限ではない |
